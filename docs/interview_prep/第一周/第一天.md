### 搞懂整个系统接入层是如何防止越权、防止泄露，以及多租户是如何隔离的？

##### 1.统一鉴权依赖。得到当前用户是谁？get_current_user

- 工作机制：
  - 请求 Header 携带 `Authorization: Bearer <token>`
  - 解码 JWT，校验 `exp` 过期时间与 `sub` (User ID)
  - 从数据库查询 `AppUser` 状态，确认是否为 `ACTIVE`

##### 2.Workspace 多租户权限校验（`require_workspace_role`）

- 工作机制：
  - 系统所有核心资源（候选人简历、职位、面试会话、知识库）都强绑定 `workspace_id`。
  - 在每个路由函数开头，调用 `await require_workspace_role(session, workspace_id, current_user.id, allowed_roles)`。
  - 查询 `WorkspaceMember` 表，校验当前用户在该工作空间内是否有 `OWNER` / `ADMIN` / `HR` / `INTERVIEWER` 等权限。
  - **防越权**：即使攻击者知道了别人的 `interview_id`，只要传入的 `workspace_id` 不属于他，或者他在该 `workspace_id` 下没有角色，直接抛出 `403 Forbidden` / `404 Not Found`。

##### 3.MCP 安全层的二次鉴权机制（`mcp_security.py`）

- 工作机制：
  - Agent 或前端通过 HTTP 调用 MCP Server 时，**绝不能让 LLM 模型自行传入 `workspace_id` 或 `user_id`**（防止 Prompt 注入攻击越权访问其他租户知识库）。
  - 后端签发带短时 TTL（如 5 分钟）和签名 `audience="interviewpilot-mcp"` 的 `auth_token`。
  - MCP Server 拿到 Token 解码出经过强签名的 `user_id` 和 `workspace_id`，再到 DB 执行 `require_workspace_role` 二次校验。
